# 01 · Quantumult X 配置文件结构

> **证据来源**：`crossutility/Quantumult-X` 官方仓库 `sample.conf`（文件头标注 `Sample Quantumult Configuration (v1.5.5 build 914)`），本文所有区块名、参数名、字段名均逐字取自该文件，未做推测。
> **标注约定**：`[官方]` = 官方文件里明确写了；`[推测]` = 由官方行为反推，未经实测；`[待核实]` = 无官方依据。

---

## 1. 区块总览

QX 配置文件是纯文本，按 `[区块名]` 分段。官方 sample.conf 出现的全部区块，按官方文件中的**实际顺序**（顺序本身不影响解析，但便于对照）：

| 区块 | 作用 | JS 相关 |
|---|---|---|
| `[general]` | 全局运行参数、检测 URL、资源解析器 | 间接（`resource_parser_url`、`geo_location_checker`） |
| `[dns]` | 自定义 DNS、DoH/DoQ、域名分流解析 | 间接（`$configuration` DNS API） |
| `[policy]` | 策略组（static / available / round-robin / ssid / dest-hash / url-latency-benchmark） | 间接（`$configuration` 策略 API） |
| `[server_remote]` | 远程节点订阅 | — |
| `[filter_remote]` | 远程分流规则 | — |
| `[rewrite_remote]` | 远程重写规则集 | ✔ 可分发脚本引用 |
| `[server_local]` | 本地节点 | — |
| `[filter_local]` | 本地分流规则 | — |
| `[rewrite_local]` | 本地重写规则 | ✔ 主要使用区 |
| `[task_local]` | 定时任务 / 事件任务 | ✔ 主要使用区 |
| `[http_backend]` | 本地 HTTP 服务，用 JS 处理请求 | ✔ |
| `[mitm]` | HTTPS 解密域名列表、证书 | ✔ 前置条件 |

**注释语法** `[官方]`：官方文件头明确 —— `Line started with ";" or "#" or "//" shall be comments.` 三种注释符都行。

## 2. `[general]` 中与脚本相关的项

`[官方]`，逐字摘自 sample.conf：

```ini
[general]
;profile_img_url =http://www.example.com/example.png
;resource_parser_url =http://www.example.com/parser.js
;network_check_url =http://bing.com
;server_check_url =http://www.google.com/generate_204
;server_check_user_agent = Agent/1.0
;server_check_timeout = 5000
;fallback_udp_policy=reject
;doh_user_agent = Agent/1.0
;geo_location_checker = http://www.example.com/json/, https://www.example.com/script.js
;running_mode_trigger = filter, filter, LINK_22E171:all_proxy, LINK_22E172:all_direct
dns_exclusion_list = *.cmpassport.com, *.jegotrip.com.cn, *.icitymobile.mobi, id6.me
;dns_reject_domain_behavior = loopback
;ssid_suspended_list = LINK_22E174, LINK_22E175
;enhanced_compatibility_ssid_list = LINK_22E174, LINK_22E175
;udp_whitelist = 53, 123, 1900, 80-443
;udp_drop_list = 1900, 80, STUN, QUIC
;excluded_routes = 192.168.0.0/16, 172.16.0.0/12, 100.64.0.0/10, 10.0.0.0/8
;icmp_auto_reply = true
```

**两个脚本入口**：

- `resource_parser_url` —— 指定一个 JS，用来自动转换第三方订阅格式。官方注释：`The resource_parser_url sample can be found at https://raw.githubusercontent.com/crossutility/Quantumult-X/master/resource-parser.js`
- `geo_location_checker = <JSON接口URL>, <脚本URL>` —— 两个参数用逗号分隔，前一个是返回 IP 归属地 JSON 的**仅 HTTP** 接口，后一个处理该 JSON。

> `[官方]` 官方在 `sample-fetch-opts-policy.js` 注释里补了一句：`built-in geo_location_checker only supports HTTP API` —— 内置的这项只吃 HTTP，想要 HTTPS 得改用 `event-interaction` 任务自己实现。

## 3. `[rewrite_local]` —— 最核心的脚本区

### 3.1 官方列出的全部重写类型

`[官方]` 逐字摘自 sample.conf 的 `[rewrite_local]` 示例块：

```ini
[rewrite_local]
;^http://example\.com/resource1/1/ url reject
;^http://example\.com/resource1/2/ url reject-img
;^http://example\.com/resource1/3/ url reject-200
;^http://example\.com/resource1/4/ url reject-dict
;^http://example\.com/resource1/5/ url reject-array
;^http://example\.com/resource2/ url 302 http://example.com/new-resource2/
;^http://example\.com/resource3/ url 307 http://example.com/new-resource3/
;^http://example\.com/resource4/ url jsonjq-response-body '.[0]'
;^http://example\.com/resource4/ url request-header ^GET /resource4/ HTTP/1\.1(\r\n) request-header GET /api/ HTTP/1.1$1
;^http://example\.com/resource4/ url request-header (\r\n)User-Agent:.+(\r\n) request-header $1User-Agent: Mozilla/5.0 ... $2
;^http://example\.com/resource5/ url request-body "info":\[.+\],"others" request-body "info":[],"others"
;^http://example\.com/resource5/ url response-body "info":\[.+\],"others" response-body "info":[],"others"
;^http://example\.com/resource5/ url echo-response text/html echo-response index.html
;^http://example\.com/resource5/ url echo-response text/html\r\nHeader-1: value1\r\nHeader-2: value2 echo-response index.html
;^http://example\.com/resource6/ url script-response-body response-body.js
;^http://example\.com/resource7/ url script-echo-response script-echo.js
;^http://example\.com/resource8/ url script-response-header response-header.js
;^http://example\.com/resource9/ url script-request-header request-header.js
;^http://example\.com/resource10/ url script-request-body request-body.js
;^http://example\.com/resource1/1/ \r\nUser-Agent: example-agent url-and-header reject
;^http://example\.com/resource1/1/ ^POST url-and-header reject
```

### 3.2 各类型的官方语义

| 类型 | 官方描述（译文/原文要点） | JS 是否需要 |
|---|---|---|
| `reject` | 返回 404 无内容；对短时间内的重复请求有 0~5 秒动态延迟 | 否 |
| `reject-200` | 返回 200 无内容 | 否 |
| `reject-img` | 返回 200，内容为 1px gif | 否 |
| `reject-dict` | 返回 200，内容为空 JSON 对象 `{}` | 否 |
| `reject-array` | 返回 200，内容为空 JSON 数组 `[]` | 否 |
| `302` / `307` | 重定向到指定 URL | 否 |
| `request-header` | 正则改写完整请求头块，可含 CRLF 匹配多个头 | 否 |
| `request-body` | 正则替换请求体 | 否 |
| `response-body` | 正则替换响应体 | 否 |
| `jsonjq-response-body` | 用 jsonjq 语法处理 JSON 响应体 | 否 |
| `jsonjq-request-body` | 用 jsonjq 语法处理 JSON 请求体 | 否 |
| `echo-response` | 直接回指定文件内容，文件放 `Quantumult X/Data` 目录 | 否 |
| `script-request-header` | JS 改请求头/路径 | **是** |
| `script-request-body` | JS 改请求体 | **是** |
| `script-response-header` | JS 改响应头/状态码 | **是** |
| `script-response-body` | JS 改响应体 | **是** |
| `script-echo-response` | JS 直接构造完整响应 | **是** |
| `script-analyze-echo-response` | 同上，但会**等待请求体** | **是** |
| `url-and-header` | URL 与请求头都匹配才生效 | 否 |

### 3.3 官方给的 7 条硬性行为约束（极易踩坑，逐条抄录）

`[官方]`：

1. **`The length and encoding related HTTP header fields will be automatically processed by Quantumult if the "rewrite" is body related, so you should not handle them by yourself.`**
   凡涉及 body 的重写，`Content-Length` / `Content-Encoding` / `Content-Type` 由 QX 自动重算。**你自己改会出错。**

2. **`The body related rewrite will not be executed if the body is empty.`**
   body 为空时不执行。所以"拦截一个无 body 的 GET 响应"这类场景，正则式 rewrite 不会触发，得用 `script-echo-response`。

3. **`The HTTP(HTTPS) request will be matched if the URL and the headers are both matched for the url-and-header rewrite (The URL will be evaluated first, and if it is not matched then the headers will not be evaluated at all).`**
   先判 URL，URL 不中就不再判 header —— 性能优化的含义。

4. **`url-and-header` 的比较字符串包含 method、path 和键值对形式的 headers**，不只是 header。

5. **脚本存放位置**：`The scripts for script-request-header, script-request-body, script-response-header, script-response-body, script-echo-response and script-analyze-echo-response should be saved in local "On My iPhone - Quantumult X - Scripts" or "iCloud Drive - Quantumult X - Scripts".`
   → 也可以直接写 http(s) URL。

6. **`script-analyze-echo-response` 与 `script-echo-response` 的唯一区别：前者会等待请求体。**（官方原文：`the former will wait for the request body`）

7. **同一请求只命中一条 rewrite 规则** —— 这条**官方没直说**，但官方 issue #124 的用户实测与回复都指向这一点，且社区普遍按此规避。标 `[推测/社区实践]`。

### 3.4 正则与转义细节

- URL 匹配用的是**正则**，不是通配符。`\.` 必须转义，`?` 表示"前一项可选"，所以 query 里的 `?` 要写成 `\?`。
- `request-header` / `response-body` 等类型的**替换内容**里，`$1 $2` 是捕获组引用。
- `echo-response` 的 content-type 参数里可以用 `\r\n` 追加自定义响应头（见官方示例第 14 行）。

## 4. `[mitm]` —— 一切 HTTPS 脚本的前置条件

`[官方]` 逐字：

```ini
[mitm]
;passphrase =
;p12 =
;skip_validating_cert = false
;skip_src_ip = 192.168.1.5, 192.168.1.6
;skip_dst_ip = 17.0.0.1
;hostname = *.example.com, *.sample.com, non-existed-domain.com, *.non-connected-domain.com
```

官方对该区块的说明，逐条：

- **`Only the TLS SNI or destination address in "hostname" will be handled by MitM. The wildcard * and ? are supported.`**
  → **匹配的是 TLS SNI（或目标 IP），不是 HTTP 里的 Host 头**。这是"域名明明写对了却抓不到"的头号原因。
- **`If the source IP of the TCP connection is matched by the skip_src_ip, the hostname will not be evaluated.`** 源 IP 命中就整体跳过。
- **`If the destination IP of the TCP connection is matched by the skip_dst_ip, the hostname will not be evaluated.`** 目标 IP 命中就整体跳过。
- **`You should always keep your CA passphrase and p12 private.`**
- `skip_validating_cert = false` —— 官方默认 false。**不要为了"让脚本能跑"改成 true**，那是拿掉上游证书校验。

**通配符规则** `[官方]`：`*` 和 `?` 都支持。`*.example.com` 是否覆盖 `example.com` 本身 —— 官方未说明，`[待核实]`，实践中普遍写成 `*.example.com, example.com` 两个都列。

## 5. `[task_local]` —— 定时任务与事件任务

`[官方]` 逐字：

```ini
[task_local]
;* * * * * sample-task.js
;* * * * * sample-task2.js, img-url=https://.../quantumult-x.png, tag=Sample, enabled=true
;* * * * * sample-task3.js, img-url=..., tag=Sample, require-devices=ID1, ID2, enabled=true
;event-network sample-task3.js
;event-interaction sample-task4.js
```

官方注释给出的四条关键信息：

1. **`Supports 5 or 6 fields of cron excluding the command field.`**
   → cron 支持 **5 段或 6 段**（不含 command 字段）。6 段时的语义（是否第一段为秒）官方未写明，`[待核实]`。**稳妥做法：只用 5 段**（分 时 日 月 周）。

2. **`The event-network will be triggered when network changed.`**
   → `event-network` 关键字，网络变化时触发。

3. **`The event-interaction will be triggered when user tapped a UIAction.`**
   → `event-interaction` 关键字，用户点 UI 操作时触发。

4. **`The event related task only can be triggered when the Quantumult X Tunnel is running.`**
   → **事件类任务只在 QX 隧道运行时才可能触发**。这意味着 `event-network` 在你关掉 VPN 开关时不会跑。

5. **`If the require-devices is set, this line of configuration will only be loaded when current Quantumult device ID belongs to the require-devices.`**
   → 设备白名单。设备 ID 位置官方指明：`Settings - Misc Settings - About`。

6. **`The $task.fetch() compose a HTTP request and deal with the response, only text body is supported.`**
   → **`$task.fetch` 只支持文本 body**（要二进制走 `bodyBytes`，见 02 文档）。

7. **`A $task.fetch() can be embeded in the completion handler of another $task.fetch(), if you want serial requests not current requests.`**
   → 串行请求 = 嵌套/链式，不是并发队列。

8. **`The default HTTP request timeout is 10 seconds.`**
   → **默认超时 10 秒**，这是硬数字，写脚本时必须按它设计。

### 5.1 `#` 哈希参数：脚本的"命令行参数"

`[官方]` 两处都写了，非常重要：

> `Just like any web browser, http(s) url string after # is never sent to the server. You can add # to the script http(s) url to append customized params, and using API $environment.sourcePath to get the whole path (...) and extract the customized params in the script by yourself.`

`sample-task.js` 里的实际用法 `[官方]`：

```ini
[task_local]
0 0 * * * https://raw.githubusercontent.com/crossutility/Quantumult-X/master/sample-task.js#force-timeout=10000&method=POST, tag=Sample, img-url=..., enabled=true
```

```js
// $environment.variables is supported since v1.5.6 build 918.
const args = $environment.variables; // { "force-timeout": "10000", "method": "POST" }
```

**要点**：
- `#` 后的内容不会发给服务器，纯粹给脚本读。
- `$environment.variables` 在 **v1.5.6 build 918** 起才有，老版本要自己从 `$environment.sourcePath` 里切。
- 参数值一律是**字符串**，`"10000"` 不是 `10000`。
- 逗号 `,` 是 QX 配置的字段分隔符，所以哈希参数里**不要再带逗号**，否则会被当成分隔截断。

## 6. `[http_backend]` —— 用 JS 起一个本地 HTTP 服务

`[官方]`：

```ini
[http_backend]
;https://raw.githubusercontent.com/crossutility/Quantumult-X/master/sample-backend.js, tag=fileConverter, path=^/example/v1/
;preference.js, tag=userPreference, path=^/preference/v1/, img-url=https://example.com, enabled=true
```

官方注释要点：

- **`After the deployment you should visit it through http://127.0.0.1:9999/your-path/your-api/.`**
  → 端口固定 **9999**，也可用 `http://quantumult-x:9999/` 或 `http://localhost:9999/`。
- **`The requests only will be sent to the related backends with the matching (regex) path.`** → `path` 是正则。
- **`Since the NE has the memory limitation, you should keep the backend as tiny as possible.`**
  → Network Extension 有内存上限，backend 脚本要小。这是硬约束，不是建议。
- 可用对象 `[官方]`：`$request.url, $request.path, $request.headers, $request.body, $prefs, $task, $notify(title, subtitle, message), console.log(message), $done(response)`

**风险提示**（我的判断）：`http_backend` 在 127.0.0.1:9999 上监听，同机任何 App 都能访问，官方明确说了 `you can use a signature or any other validation method to verify if the request is legitimate`。放敏感操作必须自己加校验。

## 7. 最小可用骨架

```ini
[general]

[filter_local]
final, proxy

[rewrite_local]
^https?://api\.example\.com/v1/user/profile url script-response-body https://example.com/scripts/profile.js

[task_local]
0 8 * * * https://example.com/scripts/checkin.js#debug=1, tag=每日签到, enabled=true

[mitm]
hostname = api.example.com
```

## 8. 与脚本相关的其他配置机制

### 8.1 URL Scheme 注入资源

`[官方]`（`url-scheme.md`）：

- `quantumult-x:///update-configuration?remote-resource=<url-encoded-json>` —— **替换**已有资源
- `quantumult-x:///add-resource?remote-resource=<url-encoded-json>` —— **保留**已有资源（v1.0.29 build 670 起）
- `quantumult-x:///ui?module=gallery&type=task&action=add&content=<url-encoded-json>` —— 添加任务库
- `quantumult-x:///ui?module=gallery&action=add`（build 672 起）

JSON 结构只认三个键：`server_remote` / `filter_remote` / `rewrite_remote`，值都是字符串数组。官方示例里的每个字符串就是配置行本身，例如 `"..., tag=Sample-01"`。

### 8.2 局域网网关模式与 MitM

`[官方]`（`lan-gateway.md`）：QX 作为网关时 **MitM 和 rewrite 对局域网内其他设备同样生效**。若那些设备无法安装/信任根证书，**必须关闭 MitM**。QX 网关模式的 DNS handler 是 `198.19.0.3`。
