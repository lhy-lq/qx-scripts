# 05 · 兼容性核实清单与「待核实」索引

> 这份文档回答一个问题：**手册里的每一条，凭什么可信？**
> 分三档标注：
>
> - **✅ 已核实** —— 官方仓库可 grep 到原文，或官方示例可直接运行
> - **🟡 部分核实** —— 官方有相关表述，但没写全（缺边界、缺返回值、缺版本）
> - **🔴 待实测** —— 官方文档完全没提，只能上真机试

## 1. 核实方法（你可以自己复现）

### 1.1 唯一权威来源

QX **没有 API 文档站**。全部权威信息只有三处，都在 `github.com/crossutility/Quantumult-X`：

| 来源 | 文件 | 提供什么 |
|---|---|---|
| 配置注释 | `sample.conf`（42 KB，约 400 行注释） | 配置语法、rewrite 类型、`$prefs`/`$notify`/`console.log`/`setTimeout` 的签名 |
| 示例脚本头注释 | `sample-*.js`（17 个） | 每个 API 的用法、参数、返回值、`@supported` 版本 |
| 协议草案 | `parser-helper-protocol.md` | `$parser` 三函数（明确标注「草案 v1」） |

### 1.2 复现命令

```bash
# 取任意官方文件（raw.githubusercontent.com 不通，必须走 api.github.com）
curl -H "Accept: application/vnd.github.raw" \
  "https://api.github.com/repos/crossutility/Quantumult-X/contents/sample.conf" \
  -o sample.conf

# 核实某个 API 是否存在（把 X 换成要查的名字）
grep -rn '\$persistentStore' sample.conf sample-*.js *.md
# 输出空 = 官方 0 处 = 不是 QX API

# 核实版本门槛
grep -h "@supported" sample-*.js | sort -u
```

> **提示**：GitHub 的 `search/code` API 需要认证（返回 401），代码搜索用不了。只能 `contents` 列目录 + 本地 grep。

### 1.3 判定规则

| 情况 | 判定 |
|---|---|
| `grep` 到官方原文，且表述明确 | ✅ |
| 官方写了 API 名和用途，但没写返回值/边界 | 🟡 |
| `grep` 结果为空，且第三方教程广泛流传 | 🔴（大概率不存在，但标待实测而非断言「没有」） |
| 官方示例能跑通，但示例之外的行为未知 | 🟡 |

## 4. 已确认「不存在」的 API（硬结论）

以下全部由 `grep` 官方仓库全量文件确认**0 处出现**：

| 名字 | 真实归属 | QX 的替代 |
|---|---|---|
| `$script` | Surge / Loon | 无（QX 不暴露脚本自身信息） |
| `$persistentStore` | Surge / Loon | `$prefs` |
| `$httpClient` | Surge / Loon | `$task.fetch` |
| `$notification` | Loon（Surge 是 `$notification.post`） | `$notify` |
| `$argument` | Surge / Loon | `$environment.variables` |
| `$utils` | Loon | 无 |
| `$crypto` | Loon | 无 |
| `$dns` | Surge（脚本类型）/ Loon（`$dns.query`） | `$configuration` 的 DNS actions |
| `$config` | Loon | `$configuration.sendMessage` |
| `Buffer` | Node.js | `Uint8Array` |
| `require` / `module.exports` | Node.js | 无（单文件脚本） |
| `process` | Node.js | 无 |
| `setInterval` | 浏览器/Node | 🔴 官方 0 处。Loon 官方明确「与 `setTimeout` 行为相同，只执行一次」 |

⚠️ **反过来说**：网上大量「Quantumult X 脚本教程」直接用了 `$persistentStore` / `$httpClient`。**看到这两个词，这个脚本 100% 不是为 QX 写的**，或者作者把 Surge 的脚本复制过来了。

### 5.1 一次性探针脚本

完整脚本见 [`examples/probe.js`](../examples/probe.js)（已落盘，可直接拷进 iPhone）。

放到 `Quantumult X/Scripts/probe.js`，`[task_local]` 加一行：

```ini
event-interaction probe.js, tag=QX探针, enabled=true
```

触发：QX 首页 → 风车 → 事件 → 「QX探针」。**必须 QX 隧道在运行**，否则 event 类任务不触发。

一次会弹 3 条通知，覆盖这些项：

| 通知里的编号 | 测的是 | 对应上表 |
|---|---|---|
| [1] [1b] | `setInterval` / `clearInterval` 是否存在于 QX 运行时 | 5 |
| [2] | `clearTimeout` 是否存在 | 5 |
| [3] | `Buffer` / `require` / `process` 是否泄漏（确认运行时干净度） | 补充 |
| [4] [5] [6] | `$prefs` 存字符串 / 对象 / 数字，读回的真实类型 | 补充（决定你该不该 `JSON.stringify`） |
| [7] | `$prefs` 空 key 会不会静默失败 | 补充 |
| [8] | `$environment` 实际有哪些字段 | 补充 |
| [9] | `$task.fetch` 在 `event-interaction` 上下文里能不能用 | 补充 |
| [10] | `$configuration.sendMessage` 是否可用 | 补充 |
| [11] | `get_running_mode` 的 `ret` 真实结构 | 12 |
| [12] | `get_traffic_statistics` 的 `ret` 字段名 | 13 |

**关键设计**：脚本本身不能假设这些 API 存在。所有 `typeof` 检查都是必需的 —— 未声明的标识符直接引用会抛 `ReferenceError`，只有 `typeof` 对未声明变量安全。这份脚本在「`$task` 和 `$configuration` 都不存在」的环境里实测也能跑完并发出 3 条通知（降级为 11 项结果 + 一句「无法测: $configuration 不可用」）。

**离线验证过**：用 Node `vm` 造了两种沙箱跑它 —— ① 全部 API 齐全（12 项结果，3 条通知）；② 缺 `$task` / `$configuration`（11 项结果，3 条通知，无异常退出）。两种情况 `$done` 都只调用一次。

**还没测的**：真机 QX 上的实际输出。把通知内容发我，我把对应的 🔴 改成 ✅ 或修正。

## 7. 版本建议

如果要跑本手册里的全部能力（`$iCloud` + `$environment.variables` + `$configuration` 全套），**最低需要 v1.5.6 build 918**。

生产环境建议：**iOS 15+ / QX build ≥ 918**。低于这个版本：

- `$environment.variables` 不存在 → 参数只能用 `$environment.sourcePath` 手解析
- `$iCloud` 需要 717+ 
- `body_bytes` 需要 480/535+ 且绑 iOS 版本
